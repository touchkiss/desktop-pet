# 空闲显示保护与猫猫魔性放大设计

## 目标

为桌面宠物增加两个相互独立但共享“用户空闲”语义的能力：用户可选择阻止 macOS 因空闲而关闭显示器，并可在真实键鼠空闲达到指定时长后自动放大猫猫。用户恢复操作时，猫猫立即恢复正常大小并重新计时；用户主动锁屏、合盖或主动睡眠仍由 macOS 正常执行。

## 范围

- 片段库设置区新增“阻止自动锁屏与关闭屏幕”checkbox。
- 保留现有全局“大小”滑块作为猫猫正常大小。
- 新增“空闲后放大”选择：`关闭 / 1 / 3 / 5 / 10 / 15 / 30 分钟`，新安装默认 `5 分钟`。
- 新增“魔性倍率”滑块，范围 `1.0×–3.0×`，默认 `2.0×`。
- 设置全部持久化，并兼容缺少新字段的旧版 `library.json`。
- 不修改系统电源或锁屏偏好，不模拟键鼠输入，不拦截手动锁屏快捷键。

## 已确认的系统行为边界

显示保护使用 IOKit 的 `PreventUserIdleDisplaySleep` 电源断言。根据 macOS SDK 的接口说明，该断言阻止显示器因用户持续空闲而自动变暗或关闭，并同时阻止系统进入空闲睡眠；它不会阻止合盖、低电量、Apple 菜单命令、手动锁屏或其他非空闲原因触发的睡眠与锁定。

这里的“阻止自动锁屏”特指由显示器空闲关闭后触发的锁定链路。应用不会改写独立的屏幕保护程序或组织安全策略；若设备由单独的屏幕保护程序、MDM 或其他安全机制主动锁定，本功能不承诺绕过。这样既满足显示器不因空闲关闭的核心需求，也不会削弱用户或组织显式配置的安全边界。

## 数据模型与兼容

`LibraryState` 增加三个可编码字段：

- `preventIdleDisplaySleep: Bool`：是否持有显示空闲休眠断言，默认 `false`；
- `manicIdleDelay: TimeInterval?`：进入魔性阶段所需空闲秒数，`nil` 表示关闭，默认 `300` 秒；
- `manicScale: Double`：相对于正常猫猫大小的额外倍率，范围 `1.0×–3.0×`，默认 `2.0×`。

旧 JSON 缺少字段时使用上述默认值。等待时长只接受界面提供的固定选项；解码到非支持值时回退到默认值。倍率在读取、写入及计算入口统一限制，非有限值回退到默认值。

## 显示保护组件

在 `DesktopPet` target 新增一个只负责电源断言生命周期的管理器：

- 启用时通过 IOKit 创建一个命名清晰的 `PreventUserIdleDisplaySleep` 断言；
- 重复启用保持幂等，不创建多个断言；
- 禁用、对象销毁及应用退出时释放断言；
- 创建失败时返回错误，由调用方把设置回退为关闭并向用户显示明确提示；
- 不调用 `caffeinate`，不生成子进程，不发送虚拟键鼠事件。

`Package.swift` 为可执行 target 链接 IOKit。`AppDelegate` 在启动、设置变化和退出路径同步管理器状态。

## 空闲检测与魔性阶段

应用使用 CoreGraphics 提供的 HID 空闲时长作为真实键鼠空闲来源。每秒采样一次，不安装全局事件监听，也不要求辅助功能权限。

阶段规则如下：

1. “空闲后放大”为关闭时，阶段始终为正常。
2. 空闲秒数小于所选阈值时，阶段为正常。
3. 空闲秒数达到或超过阈值时，进入魔性阶段。
4. 魔性阶段中一旦空闲秒数因真实鼠标或键盘活动下降到阈值以下，立即恢复正常阶段；新的空闲周期自然从该次输入重新计算。
5. 修改或关闭等待时间时立即重新评估；关闭后立即恢复正常大小。

阶段判断、支持的等待选项和倍率限制放入 `DesktopPetCore` 的纯逻辑类型，避免把系统 API 混入可测试规则。

## 尺寸计算与窗口行为

正常显示尺寸继续为：

```text
素材原尺寸 × 片段倍率 × 全局正常倍率
```

魔性阶段显示尺寸为：

```text
素材原尺寸 × 片段倍率 × 全局正常倍率 × 魔性倍率
```

鼠标互动目标素材继续使用自己的 point 尺寸，不应用魔性倍率。普通猫片段和鼠标互动猫片段均使用当前阶段倍率，保证切片或互动过程中尺寸语义一致。

阶段切换由 `AppDelegate` 主动要求 `PetWindowController` 刷新，即使当前播放帧索引没有变化也能立即生效。窗口缩放以猫猫内容的底边中心为锚点，尽量保持脚下位置不动；计算后将窗口限制在当前屏幕可见区域，避免放大后完全越界。传送、点击互动、播放和菜单操作继续运行，不因魔性阶段暂停。

## 片段库交互

在现有全局设置区域增加一行紧凑控件：

- checkbox：“阻止自动锁屏与关闭屏幕”；
- 标签与下拉框：“空闲后放大”及固定时间选项；
- 标签与滑块：“魔性倍率”，旁边显示当前倍率文本。

修改设置后立即尝试保存，并广播专用的 idle presentation settings 通知。`AppDelegate` 只在该通知路径中同步显示休眠断言、重新评估阶段和刷新倍率，不进入通用 library change 的播放重调度流程，也不清除传送期间的 hold、pending next 或 one-shot 状态。

保存失败时，设置仍在当前进程中生效，专用通知也照常发送；界面立即以“保存设置失败”提示未写入磁盘，并说明重启后可能恢复旧值。选择“关闭”时倍率滑块保留上次值但置灰；再次启用时恢复使用该值。显示保护创建失败时 checkbox 自动关闭，并显示包含系统错误码的提示。

## 错误处理与生命周期

- IOKit 断言创建失败：不保留错误的开启状态，向用户报告，应用其余功能不受影响。
- IOKit 断言释放失败：清除本地持有状态并记录可展示错误，避免后续逻辑误认为断言仍有效。
- 设置保存失败：保留当前进程中的设置并继续同步运行时行为，立即提示磁盘未写入及重启回滚风险；不得将该错误延迟成“导入失败”。
- 空闲时间 API 返回非有限值或负值：本次采样按 `0` 处理，不误触发放大。
- 当前屏幕不可用或尺寸异常：沿用当前窗口位置与正常刷新回退，不生成无效窗口 frame。
- 应用退出：先释放显示保护断言，再终止应用。
- 手动锁屏：应用不截获 `Control-Command-Q`、系统菜单锁屏、合盖或主动睡眠。

## 测试策略

XCTest 覆盖 `DesktopPetCore` 中的确定性规则：

- 支持的空闲等待选项及默认值；
- 关闭、未达阈值、恰好达到阈值和超过阈值时的阶段；
- 用户活动后从魔性阶段恢复正常；
- 魔性倍率的默认值、上下限和非有限值回退；
- 正常与魔性阶段的有效倍率计算；
- 旧配置缺少新字段时的兼容默认值；
- 非法等待时长的解码回退。

实现完成后运行完整 `swift test` 与 `swift build`。系统级行为另外人工验证：

- checkbox 开启后，超过系统显示器空闲时间仍不自动关闭屏幕；
- checkbox 关闭后，系统恢复原有空闲关闭行为；
- 通过系统菜单或 `Control-Command-Q` 手动锁屏仍成功；
- 达到每个代表性空闲阈值后猫猫放大，真实键鼠输入后立即恢复；
- 正常大小、片段倍率和魔性倍率组合后，窗口锚点及屏幕边界正确。

自动化测试只能确认逻辑、兼容性和编译链接，不能替代 macOS 电源管理与锁屏路径的本机人工验证。
