## Context

当前所有导入视频都经过同一套 ffmpeg 解码、边缘连通绿幕抠像、主体裁切和透明 PNG 序列导出流程，并作为 `PetClip` 存入同一个素材库。`ClipTag` 已支持“被摸反应”一类行为标签；`TeleportController` 已能区分随机落点与显式 `summonToCursor`，并在片段结束、拖拽和隐藏时集中取消传送。

本变更横跨素材模型、素材库 UI、播放筛选、传送生命周期和新的全局透明覆盖窗口。约束是继续支持 macOS 13、保持真实鼠标事件坐标不变、不新增第三方依赖，并确保任何退出或中断路径都不会留下隐藏的系统指针。

## Goals / Non-Goals

**Goals:**

- 复用现有抠像流水线，将任意透明动态素材配置为鼠标互动目标或猫猫互动动作。
- 为每份目标素材保存独立的 16–128 pt 显示尺寸，并提供实时预览。
- 只在随机隐现主动选择鼠标附近落点时播放一次配对互动。
- 让透明目标跟随真实鼠标，同时保留跨应用点击、拖动和滚动行为。
- 在正常结束和所有取消路径中可靠恢复指针与普通播放。

**Non-Goals:**

- 不替换 macOS 的系统光标主题，也不写入系统偏好设置。
- 不让猫猫持续追踪移动中的目标，不实现碰撞检测、命中判定或用户计分。
- 不为手动召唤、番茄钟或下载提醒触发互动。
- 不增加新的媒体格式、抠像算法或素材配对编辑器；首版分别随机选择目标和动作。

## Decisions

### 复用 `PetClip` 并增加专用配置

新增 `ClipTag.cursorPrey` 与 `ClipTag.cursorInteraction`。`PetClip` 增加可选、可兼容解码的 `CursorPreySettings`，其中 `displaySize` 默认 48 pt，并在写入和使用时限制到 16–128 pt。取消目标标签只停止素材参与选择，不删除已保存大小，重新启用时恢复用户设置。

选择此方案是因为透明帧、fps、尺寸和预览能力都已由 `PetClip` 提供。另建第二套“指针素材库”会重复导入、删除和迁移逻辑。尺寸只在显示阶段等比缩放，不重新导出 PNG，避免每次调节产生昂贵的媒体处理。

### 专用素材与普通播放隔离

普通 `playableClips`、活动队列和自动衔接候选必须排除带 `cursorPrey` 或 `cursorInteraction` 的片段。素材详情仍展示这些片段，便于预览、重命名、调节和删除。现有队列若包含后来改成专用素材的 ID，则计算播放列表时忽略该 ID；无需破坏性改写用户保存的队列。

相比允许互动动作进入普通轮播，隔离能避免在没有目标时播放抓捕动作，也避免目标素材被当成桌面宠物。两种专用标签同时存在时按专用素材处理，但 UI 应避免让同一片段同时承担两种角色。

### 只为自主随机落点准备互动

`TeleportController` 在随机传送决定落点后，仅当落点为 `.cursorNudge`、没有显式到达消息且传送由片尾随机触发时，才准备互动。控制器从两类有效素材中分别随机选择一份；缺少任一类时不改变现有提醒流程。`summonToCursor`、番茄钟和下载通知继续通过显式召唤路径运行，因此不会误触发互动。

互动动作以一次性覆盖播放方式启动：保留传送前普通播放的恢复上下文，在猫开始出现前播放选中的 `cursorInteraction` 片段，使出现特效从第一帧就使用抓捕动作。该片段结束后不参与常规 next-clip 选择，而是恢复到普通可播放集合。

### 使用点击穿透覆盖窗口呈现动态目标

新增 `CursorPreyOverlayController`，拥有一个透明、无边框、置顶、跨 Space 且 `ignoresMouseEvents = true` 的窗口。控制器按素材 fps 播放透明 PNG 序列，并通过主线程定时器读取 `NSEvent.mouseLocation`，把窗口中心持续对齐真实指针。窗口边长由该素材的 `displaySize` 决定，帧保持宽高比。

开始互动时临时隐藏系统指针；覆盖窗口仅负责视觉呈现，真实鼠标热点和事件分发完全不变。相比逐帧设置 `NSCursor`，独立窗口能稳定播放视频帧且不易被其他应用立即覆盖。相比同时显示系统指针，它更符合“替换为互动目标”的视觉目标。

### 集中且幂等地结束互动

传送控制器拥有本轮互动上下文，并通过一个统一的结束方法停止目标动画、关闭窗口、恢复系统指针、清除一次性播放状态，再恢复普通播放。该方法必须幂等，并从动作片段正常结束、拖拽或甩动、隐藏宠物、新传送、素材删除或帧加载失败、控制器停止及应用退出等路径调用。

系统指针的 hide/show 只能由覆盖控制器管理；只有成功执行隐藏后才记录为隐藏状态。由于 macOS 通常只接受前台应用发起的全局指针隐藏，覆盖控制器在互动开始时保存当前前台应用、短暂激活 DesktopPet、执行一次全局隐藏，再立即恢复原前台应用；激活失败或超时则取消互动并退回普通提醒。统一清理必须幂等显示指针，并在焦点仍停留于 DesktopPet 时兜底恢复原应用。

### 素材库 UI 使用逐素材实时配置

片段详情增加“鼠标互动目标素材”和“鼠标互动猫片段”复选框。目标标签启用时显示 16–128 pt 滑块、数值标签、恢复 48 pt 按钮，以及按当前值播放透明帧的预览。每个片段读写自己的 `CursorPreySettings`，因此不同素材可以独立保存苍蝇、小虫、逗猫棒或猫玩具所需大小。

## Risks / Trade-offs

- [系统指针隐藏与恢复不平衡] → 由单一控制器持有状态，集中幂等清理，并在停止和应用退出时兜底恢复。
- [跨显示器时覆盖窗口位置或缩放跳变] → 每次跟随都使用全局屏幕坐标，并手工验证不同缩放比例的多显示器组合。
- [目标高速移动而猫停在落点附近，互动感减弱] → 首版保持真实鼠标自由和短时单次动作；持续追踪猫的位置不在本次范围。
- [专用标签导致普通播放集合为空] → 播放器保持安全停止状态，UI 仍允许用户修改标签；不把专用素材偷偷回退到普通播放。
- [高 fps 或大源帧增加解码/内存压力] → 沿用现有按帧加载方式，覆盖层只按配置尺寸显示且在结束时释放帧引用和定时器。

## Migration Plan

`CursorPreySettings` 使用 `decodeIfPresent`，旧 `library.json` 缺少该字段时按 `nil` 解码；现有片段保持普通素材身份。部署不需要批量迁移，用户可在详情页逐个标记和调整。回滚时旧版本会忽略无法识别的新增键；标签为字符串数组，不影响旧版读取其他数据。

## Open Questions

无；素材类型、逐素材大小、触发范围、覆盖方案和结束规则均已确认。
